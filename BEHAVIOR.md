## Gaps (honest)

- **G1 — `ignorable` marker not settable on `session.append`.** DSH `Session.append(type,data)` writes `{type,seq,time,data}` only; the `ignorable` envelope field exists on `SessionEvent` but `append` never sets it (dsh-session/lib/index.js L1400-1421). Consequence: our custom `dsh-caveman/*` events are *non-ignorable*; a DSH build without this plugin that resumes such a session will refuse (`KNOWN_SESSION_EVENT_TYPES` check at index.js:298 only exempts `ignorable===true`). Pi's `appendEntry` had the same additive-custom-type semantics, so behavior parity holds; the risk is *forward portability* of sessions if the plugin is uninstalled, identical to Pi where the custom entries were inert anyway. Mitigation: none available without core changes — plugin event types cannot be registered. Left as-is; append failures are caught (`try/catch`) so worst case the level simply doesn't persist.
- **G2 — `/caveman config` interactive SettingsList dialog.** Pi used `ctx.ui.custom` + pi-tui `SettingsList`. dsh-TUI exposes `ctx.tuiDialogs` (select/confirm/input) — a two-step `select` for defaultLevel + `confirm` for showStatus would work but is not a faithful port; chose informational text return instead (`/caveman config` prints current config + where to change it). Status: **gap** (settings still changeable via the caveman.json file + `/settings` schema rows).
- **G3 — Pi `ctx.ui.notify` color names.** Pi used `"info"`/`"warning"`/`"error"`; DSH toast colors are `success|warning|error`. Mapped `info→success` (closest semantic for positive confirmations).
- **G4 — `tui/input` grant dependency.** Without `session.input.intercept` granted in `~/.dsh-tui/extension-grants.json`, `ctx.on('tui/input')` is denied at subscribe time (warned + no-op disposer). Fallback `agent/inbox/inserted` keeps deactivation working but cannot prevent delivery — which coincidentally matches Pi exactly (Pi never consumed the line either).
- **G5 — `ctx.ui.setStatus` styling.** Pi called `theme.fg("muted",…)` for label styling; DSH `tuiStatus.set` takes plain text (control chars stripped — ANSI escapes from caveman.ts's `\x1b[38;5;…` frames may be stripped by the sanitizer). Frames still animate via text change; colors may flatten to theme default. Minor visual divergence, not functional.

## Not needed / built-in

- Ponytail skills themselves (`/skill:ponytail-*` execution) — already synced into `~/.dsh/skills` (symlinks to the Pi repo); skill aliases just queue the text.
- `session_shutdown` cleanup — cordis disposes plugin effects on unload; `cavemanTimer` is cleared in `syncCavemanStatus` on level change; process exit kills the interval anyway (plugin lifecycle is the host's).
